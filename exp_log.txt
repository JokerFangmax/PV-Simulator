# Task
Based on a comparison with PhysCtrl's physics-aware training, I need to add explicit physical conservation losses to `train_stage1.py` to prevent point cloud collapse during collisions. PhysCtrl uses `loss_momentum` and `DeformLoss` (MPM-style) to maintain physical consistency.

My dataset has the following fields (per .npz sample):
- `x_s_raw`: (T_raw, N, 9) — positions(3), velocities(3), angular_velocities(3)
- `c_force_raw`: (T_raw, N, 6) — force vectors(3), contact points(3)
- `c_floor`: scalar — floor height
- `c_mass`: (n_obj,) — mass per object
- `c_mat`: (n_obj, 2) — friction, restitution per object
- `c_static`: (n_obj,) — static flag
- `point_obj_idx`: (N,) — maps each point to its object index

Please implement the following two losses in `train_stage1.py`:

## 1. Momentum Conservation Loss
For each object in each frame:
- Compute per-point mass: if per-point mass is not in the data, distribute `c_mass[object]` uniformly across the object's valid points.
- Compute predicted total momentum: `P_pred = sum(mass_i * velocity_pred_i)` for the object's points.
- Compute target total momentum: `P_gt = sum(mass_i * velocity_gt_i)`.
- Loss: `‖P_pred - P_gt‖²` (squared L2 norm of total momentum vector difference).
- Also compute angular momentum if feasible: `L = sum(mass_i * (r_i × velocity_i))`, but this is optional.

Add CLI argument `--lambda_momentum` (default 0.01).

## 2. Floor Penetration Loss
For each point in each frame:
- If the position coordinate corresponding to gravity direction (assume z-axis or y-axis; detect from data distribution or use a CLI arg `--gravity_axis z`) is below `c_floor`:
- Penalty: `max(0, c_floor - position_axis)²`
- Only apply to non-static objects (`c_static == 0`).

Add CLI argument `--lambda_floor` (default 0.1).

## 3. Integration
Add both losses to the total loss aggregation:
```python
loss = (
    diffusion_loss
    + args.lambda_vel * velocity_loss
    + args.lambda_local_dist * local_dist_loss
    + args.lambda_covariance * covariance_loss
    + args.lambda_chamfer * chamfer_loss
    + args.lambda_momentum * momentum_loss
    + args.lambda_floor * floor_loss
)

## 4. Constraints
* All losses must respect point_mask (ignore padded points).
* momentum_loss should be computed in raw space (after AE decode) or in latent space if you can derive per-point velocity from the latent state. Prefer raw space for physical correctness.
* floor_loss must be computed in raw position space.
* Do NOT modify the AE architecture or the diffusion pipeline.
* Do NOT assume the existence of vol, F, C, or other MPM-specific fields unless they are already present in the data.

# Output
* Exact code diffs for train_stage1.py.
* Show how c_mass and point_obj_idx are used to compute per-object momentum.
* Show how c_floor and c_static are used for floor penetration.
* Provide a smoke-test command that runs 100 steps with both new losses enabled.

## Task: Redesign PhysicsDecoder to Use Full Geometry for Pose Prediction

### Current Fatal Flaw (Confirmed)
The existing `PhysicsConditionedRigidResidualDecoder` at `/data/fhr/projects/PV-Simulator/videox_fun/models/physics_rigid_decoder.py` pools per-object latent via:

```python
pooled[b, :, obj_id] = latent[b, :, points].mean(dim=1)
```

This mean-pooling discards all shape/rotation information. The SE(3) pose head (axis-angle + translation) therefore cannot predict rotation from a centroid alone. For rigid bodies (`stiffness=1.0`, `deformability=0`, `residual=0`), the output is purely `SE3(canonical)` with wrong rotation, causing trajectories to be completely incorrect.

### Redesign Requirements

#### 1. Pose Prediction Must Use Full Geometry
Replace the centroid-pooling pose prediction with a **differentiable correspondence-based rigid alignment** or **geometry-aware pose prediction**.

Recommended approach (choose one, justify your choice):

**Option A: Differentiable Kabsch/Procrustes SE3**
- Do NOT predict axis-angle/translation from a pooled vector.
- Instead, compute the optimal rigid transformation between `canonical_points` and `pred_x0_pos_raw` using differentiable Kabsch algorithm (SVD-based).
- The "pose network" is replaced by a differentiable geometry solver.
- Input to the solver: `canonical_points` and `pred_x0_pos_raw` (both `[B, T, N, 3]`).
- Output: `R` (rotation matrix) and `t` (translation) per object per timestep.
- This guarantees the coarse output is the **best rigid fit** to the predicted coordinates, not a learned guess from a centroid.

**Option B: PointNet-style Feature Aggregation**
- If you must keep a learned pose head, aggregate per-point features using max-pooling (not mean-pooling) over the full point cloud to preserve shape information.
- Use a small PointNet/MLP on `canonical_points` to extract a rotation-equivariant feature.
- Predict SE3 from this full-shape feature.

**Option C: Hybrid**
- Use Kabsch to compute initial SE3 from `pred_x0_pos_raw` vs `canonical`.
- Use a small residual network to predict a correction delta to the Kabsch SE3 (for handling soft bodies later).

We recommend **Option A** for rigid bodies because it is deterministic, differentiable, and guaranteed to find the optimal rigid alignment. It also removes the "pose network" entirely, eliminating the gradient bottleneck.

#### 2. Residual Branch Design
- For rigid bodies (`stiffness=1.0`), residual should remain near zero.
- For future soft bodies, residual should be per-point and conditioned on physics.
- The residual head should take per-point latent (not pooled) and output per-point displacement.

#### 3. Inference Pipeline Integration (CRITICAL)
The `SimulationPipeline` at `/data/fhr/projects/PV-Simulator/videox_fun/pipeline/pipeline_simulation.py` currently does NOT load or use `physics_decoder.pt`. You must:

- Add `physics_decoder` parameter to `SimulationPipeline.__init__`.
- Load `physics_decoder.pt` from the checkpoint directory in `from_pretrained` or initialization.
- In the forward pass, after `ae.decode()` produces coordinates, pass them through `physics_decoder` (with `canonical_points` from the first frame, `physics_attrs`, and `point_obj_idx`).
- Return the decoder's output as the final prediction.

#### 4. Training Loop Compatibility
The redesigned decoder must maintain the same interface as the current one so `train_stage1.py` requires minimal changes:

```python
decoder_out = physics_decoder(
    latent=pred_x0_pos_raw,          # (B, T, N, 3)
    canonical_points=canonical_points, # (B, N, 3)
    physics_attrs=physics_attrs,       # (B, num_objects, 4)
    point_obj_idx=point_obj_idx,       # (B, N)
    point_mask=point_mask,             # (B, N)
)
```

Return dict must contain:
```python
{
    "positions":        (B, T, N, 3),  # final output
    "coarse_positions": (B, T, N, 3),  # SE3-only output
    "residual":         (B, T, N, 3),  # deformation residual
    "deformability":    (B, T, num_objects, 1),  # learned gate
}
```
